# PostgreSQL reference-image caller assessment, 2026-11-25

Scope: reference image `postgres:17-bookworm@sha256:1eff563f6c868b9b433566e9f3cf6e5c79fbd3b95bf70ec7277d376cdbfc50d7`; supported RateFreak database and coordinated maintenance paths. This is a focused caller assessment, not clearance of the full image. No persistent instance was accessed. No product files were changed.

## Evidence

- `image-linkage.txt`: actual image inspected using `docker run --rm --network none --read-only --entrypoint sh`; PostgreSQL server links libxml2, libzstd, zlib and libgssapi_krb5. pg_restore links libzstd, zlib and libgssapi_krb5. Versions: libxml2 2.9.14+dfsg-1.3~deb12u6; libzstd1 1.5.4+dfsg2-5; zlib1g 1:1.2.13.dfsg-1; GSS libraries 1.20.1-2+deb12u5. krb5kdc, kadmind, xmlcatalog and /etc/krb5.keytab absent from the image.
- `postgresql-17.12/` is the already-retained upstream source tarball `9cf136a703d8ee2f83465c43be4e9e8e7930c82b0bfba13be7e2537be769ac55-postgresql-17_17.12.orig.tar.bz2`. This is upstream source, not a fully patched Bookworm PGDG source tree; distro-patch differences remain a limit.
- Existing downloaded vendor/debian-tracker.json and vendor/debian-cve-list.txt were consulted, including current Bookworm status, not earlier trial classifications.
- `acquisition.json` records URLs, acquisition UTC and SHA-256 hashes for retained MIT advisory, vendor announcement, upstream fixes and zstd announcement. The full MIT advisory is https://web.mit.edu/kerberos/advisories/MITKRB5-SA-2026-001.txt .
- Reference compose has no published PostgreSQL port; only API/tools join the database network. database.sql creates password roles; no Kerberos config/keytab is mounted. Absence of a published port limits exposure but does not remove library paths reachable from the database network.

## zlib

**CVE-2023-45853:** Debian explicitly says contrib/minizip is not built into these src:zlib binary packages. Conditional component exclusion applies to zlib1g; it does not generalize to separate Minizip or embedded copies.

**CVE-2026-85091:** Installed Bookworm 1.2.13 is affected by vendor range, but this version requires a failed underlying write followed by gzclearerr(), then another gz* write. Exact PG17.12 src search has zero gzclearerr calls. pg_dump/compress_gzip.c:Gzip_write (around line 298) terminates via pg_fatal on gzwrite failure. Custom-format archive compression uses deflate/inflate (same file lines 77-229), not the gz* file API. RateFreak maintenance.py:104 requests `pg_dump --format=custom` without a compression override. These facts support excluding the concrete supported pg_dump/custom-format/pg_restore call sequence from this CVE, not asserting that the installed zlib is patched or every program in the image is safe. A future gzclearerr retry implementation or separate gzip-writing caller requires reassessment.

## zstd CVE-2026-124851

The vendor confirms disclosure of stale/uninitialized data through crafted compressed input and observable output; upstream fix corrects retained frame history and decoder-owned literal padding. The library is genuinely linked; this is not a package-only false positive.

- pg_dump.c:783-796 defaults custom and directory backups to gzip when zlib is available. RateFreak coordinated backup gives no zstd override. Supported backups generated by that path are not attacker-controlled zstd frames.
- Real affected caller exists: pg_dump/compress_zstd.c uses ZSTD_decompressStream and writes decompressed output to archive consumers; pg_restore accepts zstd-compressed archives. Therefore an exclusion must explicitly cover only own coordinated gzip backups, not arbitrary imported or operator-selected zstd backups. A malicious zstd archive can enter the decoder if operators import such an archive. New tools use Debian13 fixed zstd, but that does not patch the reference database image's copy of pg_restore.
- Server's identified ZSTD_decompress use is src/backend/access/transam/xlogreader.c:2122, decoding compressed WAL full-page images. There is no PostgreSQL wire-protocol compression that maps ordinary query values to this decoder. Crafted WAL/replication, changed wal_compression configuration and physical-backup workflows require separate assessment; these are not RateFreak's coordinated logical-backup path. No blanket exclusion for all server use is justified.

## libxml2

SQL/XML is actually compiled and linked. src/backend/utils/adt/xml.c:1844 uses XML_PARSE_NOENT | XML_PARSE_DTDATTR, parses internal DTDs, and explicitly blocks external entity access with xmlPgEntityLoader (2004-2010). External access blocking does not establish safety against internal entity/parser memory bugs. Direct authenticated SQL can call XML input/SQL/XML built-ins; treating all authenticated SQL as trusted would be wrong.

- CVE-2026-6653 (xmlParseInternalSubset UAF): parser/internal-DTD path is credible for direct SQL callers; external-entity deny does not prove exclusion.
- CVE-2026-86138 (xmlDictAddQString overflow): XML parsing/dictionary path is present; limits on names/document sizes might constrain the exact overflow but were not proven against the installed patched libxml2 source. Retain as conditional unresolved SQL/parser exposure.
- CVE-2026-86140 (xmlSnprintfElements overflow): DTD validation diagnostic function. PostgreSQL does not request XML_PARSE_DTDVALID in inspected core parsing paths, but a complete patched-library caller proof was not performed. Do not conflate DTDATTR with DTDVALID. This is narrower than claiming no XML use.
- CVE-2026-86142 (xmlXPtrEvalXPtrPart): no xmlXPtr call in PostgreSQL17.12 src. Core SQL xpath uses xmlXPath* APIs, which are distinct. Conditional core-path exclusion; extensions could change it.
- CVE-2026-86144 (xmlXIncludeProcess[Tree] flags): no XInclude processing call in PostgreSQL17.12 src; conditional core-path exclusion. External entity deny is additional defense but not the sole rationale.
- CVE-2026-74860: Python SAX attributeDecl binding bug. PostgreSQL SQL/XML uses C APIs; the image lacks python3-libxml2 in the scanned package list. Conditional component/caller exclusion, not a general XML exemption.
- CVE-2026-86143: unsafe integer conversion before XML output write callbacks. PostgreSQL uses xmlSaveToBuffer/xmlSaveDoc/xmlSaveTree and XML writers in xml.c; cannot dismiss simply as a missing XML client. Exact callback/size reachability not established here. Retain unresolved for arbitrary SQL/XML use pending installed-library analysis.
- xmlcatalog-specific CVE-2026-11979 is outside these library paths; executable absent in actual image. (It is not one of the seven HIGH libxml2 findings in this scan.)

Repository search of src code/migrations found no xmlparse, xpath, XML column mappings or XML SQL call sites. Ordinary application text/JSON fields are not implicitly XML-parsed. This supports a bounded statement that current supported application queries do not route external content to SQL/XML; it does not clear arbitrary operator SQL, added XML columns, extensions, imported schemas, or compromised DB credentials.

## Kerberos: do not rely solely on SCRAM pg_hba

**Important evidence gap / potentially reachable parser:** PostgreSQL backend_startup.c:625-659 accepts a GSSENCRequest before pg_hba authentication selection for non-Unix, non-SSL connections. be-secure-gssapi.c:602 passes the incoming token to gss_accept_sec_context with GSS_C_NO_CREDENTIAL. Token size is capped at 65532 bytes (constant at line 59; guard at 582). Thus no `gss` pg_hba rule and no keytab do not prove that the GSS parser is unreachable.

- CVE-2026-119079: upstream fix 782e5ac explicitly describes unauthenticated CPU denial of service in KDC **or application server** from repeated ASN.1 SEQUENCE OF reallocations. PostgreSQL calls the relevant GSS library before DB authentication. No proof was made that lack of a keytab or the 64KiB cap prevents the bad decoder sequence before rejection. Keep unresolved/conditional and do not classify it KDC-only based on scanner title.
- CVE-2026-107364: scanner description identifies KDC read overrun, but shared ASN.1 decoder use and the MIT umbrella advisory's application-server warning require exact-function/caller proof before treating as KDC-only. This investigation did not obtain a precise affected token/ordering proof. Keep explicit evidence gap.
- CVE-2026-112315/112316/112318/112319/112320/112321/112322/112323: descriptions identify libgssrpc/kadm5 RPC decoding or kadmind server paths. Actual postgres/pg_restore linkage includes libgssapi, not libgssrpc; neither KDC nor kadmind daemon is installed. Conditional component/protocol exclusions for supported PostgreSQL wire/GSS use; not an exemption for all Kerberos clients.
- CVE-2026-112317: KDB keytab decryption error path for KDC/kadmind. No KDC database/keytab backend or daemon in reference config. Conditional KDC-role exclusion.
- CVE-2026-118380: unverified RPCSEC_GSS service-type protection in libgssrpc. PostgreSQL uses PostgreSQL protocol plus GSS contexts, not kadm5/iprop RPC. Conditional protocol exclusion.
- CVE-2026-71200: KDC PKINIT preauthentication NULL dereference. No KDC/PKINIT service in reference; conditional server-role exclusion.
- CVE-2026-71199: CAMMAC authentication-indicator bypass. Reference has no Kerberos realm/keytab, GSS authentication rules or auth-indicator policy. Conditional authorization-flow exclusion; vendor says KDC update prevents it. Must re-evaluate for Kerberos-enabled external DB configurations; not proof that linked library is fixed.

## Tracker/source-advisory limits

No TEMP entries for libxml2/zlib/libzstd/krb5 were open in the retained Bookworm tracker data. Other installed source packages do have TEMP entries (bash, libseccomp, shadow, sysvinit, tar). The JSON omits descriptions, but raw debian-cve-list.txt:3953-3980 supplies seven libseccomp GHSA titles, links and fixes; those must not be called evidence gaps merely because IDs are temporary. Full GHSA caller assessment for these other components was outside this focused review. A source advisory with no usable technical details remains an external evidence gap and cannot be converted into a clean security claim from scanner absence.

Conclusion: concrete supported-path exclusions exist, but PostgreSQL119079/shared-ASN.1 and arbitrary SQL/XML details remain conditional/unresolved. This note does not establish release security clearance.
