# API network-library supported-caller assessment

Exact candidate API image: `sha256:3984e4af4f632a888cdb60337103b44bc8c88a9450e89631761fef1b87e822e0`. The independent ephemeral probe used the image default UID10001, no network, read-only root/mount, no-new-privileges and all capabilities dropped. No installation or instance credentials were mounted. `api-probe.json` records results, `api-probe.log` is empty, exit0.

## Positive and negative evidence

- GnuTLS, Kerberos/GSS, Cyrus SASL, RTMP and LDAP libraries are installed. `ldd curl` positively shows them loaded as transitive dependencies. `curl --version` identifies OpenSSL3.0.13 as curl's TLS backend. These exclusions do not rely on a false unloaded/absent-library claim.
- Exact compose API healthcheck is `curl --fail --silent http://api:8080/health/ready`. It neither follows redirects nor supplies auth credentials, LDAP or RTMP protocol. All provider HttpClient registrations explicitly select SocketsHttpHandler (`src/RateFreak.Infrastructure/DependencyInjection.cs:102-139`), and OAuth selects it too (`src/RateFreak.Api/Security/ExternalIdentityReader.cs:98`). Existing exact-image OpenSSL binary/source evidence identifies the .NET crypto PAL. This scopes GnuTLS certificate-verification and RTMP/AMF findings away from the supported network call paths while preserving that their libraries exist.
- No KDC/kadmind/admin clients/KDB plugins/libgssrpc/libkadm5 are present at the examined standard runtime paths. Application authentication registers Identity cookies/Google/GitHub OAuth, with no Negotiate acceptor handler. This excludes server/admin/RPC service triggers in the supplied advisories. Generic library presence alone is not an exposed server.
- Reference image has no `/etc/krb5.conf`, keytab, KRB5 environment variables, or standard cache candidates. Actual `gss_acquire_cred` for default INITIATE usage returns major458752/minor2529639053 and no credential handle. Npgsql10 **does** attempt GSS credential discovery by default; it must not be described as never loading Kerberos. Official [Npgsql security documentation](https://www.npgsql.org/doc/security), verified 2026-11-25, says Prefer selects GSS session encryption when credentials are present and otherwise falls back. Supplied compose has no credential/keytab mounts or Kerberos configuration. Existing managed connection string includes password credentials. Custom Kerberos configuration would invalidate this condition.
- SASL directory contains only `libsasldb` files; no DIGEST-MD5 plugin. The vulnerable DIGEST-MD5 plugin is not a supported app authentication mechanism. Managed PostgreSQL SCRAM is not the Cyrus plugin merely because both are SASL mechanisms.
- Exact-image probe verifies `genrb` absent. ICU runtime globalization remains available; its use does not invoke the genrb compiler's affected routine.

`assessments.json` contains one record per ledger advisory (26 API records), exact image reference, required attack condition, caller evidence and configuration limits. These are scoped caller/affected-component exclusions, not package fixes, general-library guarantees, or overall release clearance. No product files changed. Broader sources such as gnupg/python/shadow/util-linux are outside this file.

## Bounds

The ephemeral probe does not inspect an actual installation or its protected secrets. It verifies immutable reference-image defaults, matched to the shipped compose/source contract. Injected credentials, new mounts/environment, proxies/curl config, added authentication handlers/plugins, LDAP/RTMP clients or arbitrary local commands need reassessment. Default GSS credential discovery is observed but no complete database authentication or TLS handshake was synthesized by this probe. The parent application's full acceptance tests provide separate database-flow coverage.

Independent exact-image `api-remaining-probe.py` loads the entrypoint as a non-main module without initialization or instance access: no XML parser modules are loaded; subsequent availability checks positively confirm pyexpat/ElementTree remain installed. gpgtar is absent. API entrypoint uses JSON/filesystem/OS utilities and replaces its process with .NET; curl performs its healthcheck. No supported Python XML parser or gpgtar invocation appears in the source/AST command graph. These are supported-caller exclusions, not parser repairs. Probe exit0/empty stderr.
