# RateFreak 0.1.0

Local stable candidate; publication and final release qualification are pending.

## Changes

First self-hosted release candidate: accounts with saved-code recovery and optional
linked sign-in; private libraries, ratings, reviews, comments, profiles, follows,
feeds and notifications; custom catalog items, uploads and ordered collections;
reporting, moderation and staff management.

Optional catalog providers cover TMDB movies/TV, IGDB games, Open Library books,
and MusicBrainz albums and songs with associated-release artwork. TMDB and IGDB
content refresh/expiry and independent removal policies protect user content and
restore operations. Provider eligibility, registration, attribution and pacing
remain installation responsibilities; providers default to disabled.

The reference installation includes API/web/tools images, manual migration and
release loading, HTTPS ingress, coordinated backup/restore, source/notice delivery
and optional administrator update checks. Runtime configuration retains the
single-arena allocator policy, restricted image/Node decoders and disabled
PostgreSQL JIT used in the security follow-up.

## Upgrade

Supported reference target: single-host Linux amd64, Next.js to .NET to PostgreSQL
17.12 on Trixie. This is the first stable-channel candidate; no preceding
published stable bundle exists. Qualification uses the pinned synthetic
source-build baseline `9cc808aa86d6510802d9189d34df5e9bffe2d0b8`.

Stop all writers, retain previous image identities and a coordinated protected
database/artwork/Data Protection key backup, and preserve the independent current
erasure journal and TMDB/IGDB policy records. Follow docs/self-hosting.md: load the
matching release (or build matching source), prepare, explicitly migrate, then
start. Review PostgreSQL collation handling and provider/runtime configuration.
Existing installations require their own reviewed upgrade; local development
migration evidence is not acceptance for another installation. Upgrades are manual.

## Migrations

The final schema migration is `20261127222703_AddSongs`. The candidate also
includes `20261124233146_AddTmdbContentLifecycle` and
`20261127171719_AddIgdbContentLifecycle`, alongside earlier application migrations.
Run the matching tools migration bundle explicitly; startup acceptance binds to
all three image identities. Provision durable protected artwork, lifecycle
cache/policy paths and current erasure/policy records before starting writers.
Do not apply this candidate to a persistent installation without reviewing its
migration and coordinated recovery procedure.

## Recovery

Keep matching prior artifacts and protected coordinated database/artwork/key
backups with the current independent erasure journal and TMDB/IGDB policy records.
Backups expire within 30 days. Leave writers stopped on migration failure. Use a
reviewed forward fix or restore matching-version data/artwork in isolation and
replay current erasure and provider policies before exposing restored content.
Do not run old application images against a changed schema or assume a schema
downgrade preserves new song/provider lifecycle data.

## Known issues

This candidate is not approved for public distribution. Matching source/notice
coverage, all-layer secrets/privacy inspection, fresh dependency/security review,
exact-candidate installation/upgrade/browser/recovery acceptance, representative
load evidence and maintainer security-report notification delivery remain gates.
Earlier security exclusions and accepted risks need binding to these exact
artifacts; no previous candidate clearance transfers automatically.

Only single-host Linux amd64 is the supported reference topology; multi-replica
abuse budgets and other architectures remain unqualified. Optional provider and
Google/GitHub integrations require operator setup and applicable eligibility.
Administrator update checks default to disabled and require GitHub connectivity
when enabled. Original font download/subsetting history and exact upstream sharp
prebuild resolution retain their documented provenance limits. See docs/STATUS.md,
docs/releasing.md and docs/security-risk-policy.md for release and operator duties.
