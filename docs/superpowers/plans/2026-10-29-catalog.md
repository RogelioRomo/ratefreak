# Canonical catalog implementation plan

> Execute inline with superpowers:executing-plans; verify each deliverable.

Goal: persist canonical movie/TV records and expose bounded public catalog reads.
Architecture: Domain entities, Application read contracts, Infrastructure EF query,
Api Minimal API routes. Existing .NET 10 / PostgreSQL 17 dependencies only.
Spec: ../specs/2026-10-29-catalog-design.md and ratefreak-plan.md §5.2, Phase 2.

## Constraints and review focus

- No frontend, external HTTP, public writes or seed data.
- Real PostgreSQL migration tests; stable external identity namespace and FK rules.
- Literal wildcard searches, stable pagination ties, malformed/overflow query input.
- JSON object metadata and stable movie/tv_show values enforced in PostgreSQL.
- No automatic startup migrations; preserve existing data.
