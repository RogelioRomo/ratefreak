# TMDB integration implementation plan

> Execute inline using superpowers:executing-plans and test-driven-development.

Goal: normalized TMDB movie/TV search, preview and idempotent authenticated import.
Architecture: Application provider/import contracts; Infrastructure typed HttpClient
adapter, bounded outbound gate and transactional EF import; API routes/security.
Tech: existing .NET 10 framework and PostgreSQL, no SDK/resilience package required.
Spec: ../specs/2026-10-29-tmdb-design.md; ratefreak-backend-plan.md §6 and Phase 3.

## Constraints/review focus

- No token in source, URL, logs or public contracts; disabled adapter does no HTTP.
- Fixed HTTPS hosts, no redirects; bounded time/concurrency/body size and retry count.
- Provider failures, malformed fields, cancellation and rate-limit headers stay distinct.
- Concurrent/repeated imports preserve identity atomically; movie/TV namespaces differ.
- Authentication/CSRF and per-user import limits apply; never trust client metadata.
